# 评测、修订与行为场景

## 先定义验收，再看答案

划分时间连续且不重叠的训练、调参、最终留出期间；关联公司/客户、同一报告的不同页不是独立样本。固定模型、工具、可用背景、数据预算与输出格式。通过隔离的生成上下文或目录白名单隐藏对应参考报告/反馈；若宿主无法隔离，记录污染风险，不称为严格盲测。

验收优先级：

1. **事实门槛**：关键数字独立重算；汇总核对；无未解决的关键单位/分母错误，无无依据因果结论。超过约定容差的关键错误不被文风得分抵消。
2. **分析质量**：主要变化与异常覆盖、证据充分性、排序是否符合重要性、可执行建议和必要的不确定性。
3. **交付质量**：在已声明业务范围内无需分析师补写的完整交付率、关键遗漏、图文一致性与可读性、运行时间和费用。人工修改量仅作为研发诊断。

“替代分析师”按项目任务验收：不能用一个数字准确率或模板渲染成功代表整项工作。自动检查验证数据、指标与来源；智能体核验问题覆盖、解释和渲染结果；开发期独立评测验证系统能力。常规周期不设强制分析师改稿关卡。未回答的必答问题、未定义的分母和无来源的核心解释阻断完整交付；系统先自行修复，确实缺输入才请求业务方补充。

规则和测试不可只照搬生成算法。固定一组人工可算的数字、独立重算及边界案例；LLM 对比仅作为软评价。原报告错误也应被标记。参考报告之外的新洞察需单独核实。

## 三组消融

- A：通用适用方法＋完成计算所必需的企业数据契约，不使用历史习得规则。
- B：相同契约＋历史报告提炼规则，不增加方法库中的额外分析。
- C：相同契约＋历史规则＋适用方法。

三组使用相同事实校验标准与数据可见范围，不能通过让 A 缺必要业务口径人为制造劣势。输出匿名、顺序打乱，让业务人员评价准确、遗漏、实用及修订量。小样本不报告虚假的统计显著性；没有真人评测就明确软评价由模型完成。

比较分析方法时，三组采用相同视觉规范，避免把漂亮排版当成分析提升；视觉质量单独评价。视觉规范仅从训练材料或预先给定的品牌模板提炼，不能读取留出报告来选择最像答案的版式。

## 视觉验收

按照 [视觉逆向规程](visual-reverse-engineering.md) 独立记录结构检查、逐页渲染检查和内容压力场景。记录可编辑性、品牌/语义颜色一致性、层级、布局、图文可读性与内容适配；不以全页像素相似度作为总分。缺字体或无法渲染时明确未验证范围。没有真实报告时只能检查规程与规则完整性，不能称为模板还原验证。

## 修订归因

速度按 [执行与性能规程](execution-performance.md) 记录冷/热缓存、历史修订、阶段耗时和可获取的模型开销，区分构建与周期运行。比较性能时保持输入、输出格式/页数、模型设置和质量门槛一致；增量/缓存结果需与全量重算核对关键指标及证据状态。辅助计时脚本测试不代表业务流水线提速。

多视角与叙事按 [综合规程](analysis-synthesis.md) 验收：问题覆盖和未回答项、证据去重、冲突是否解决或清晰披露、摘要与正文一致、行动强度与证据匹配。比较新增能力效果时固定数据、模型、视觉规范及其他规则，只启用/关闭相应问题清单或叙事组件；章节数量和角色数量不是质量指标。

数据解析错误先修解析；指标口径错误先修契约与测试；规则正确但没被选中改触发描述；只在多期或明确业务定义支持时扩大规则。读过一条规则不证明效果由它造成，必要时用有/无该规则的消融判断。

记录版本、修订理由、失败案例和前后结果。默认两轮修订后若未达到门槛，停止为候选并报告问题。最终留出成绩下降不得覆盖此前更好版本；发布与否说明适用范围。使用最终留出结果修订后，必须重新收集未见样本才能获得新的留出证据。

## 本 skill 行为演练（场景定义，不代表已通过）

指标与假设验收另核对：指标 ID/版本及可加性明确；A/B 来源有同范围快照；差异项不重复计数且残余可见；假设结果区分支持/否定/需重验；失效影响包含派生结论、建议与图表。不能以日志完整替代重算证据。

| 场景/最小输入 | 期望可观察行为 | 失败表现 |
|---|---|---|
| 只有一期 Excel 和报告 | 产出候选规则与证据，说明尚无跨期证据 | 宣称已具备泛化能力 |
| 只给方法论和字段定义 | 构建方法论驱动候选，列出真实样本需求 | 编造历史报告或训练结果 |
| 公式存在但缓存为空 | 标记指标阻塞，提出副本重算或独立计算 | 将空值当零算出结论 |
| 原报告说下降由竞品促销导致，表中只有销量 | 将原因列为外部证据需求/假设 | 将促销写成确定事实或周期规则 |
| 主表两条交易，维表同键两行 | 在 join 前发现多对多风险并阻断金额翻倍 | 合并后直接求和 |
| 当前80、上期100，参考报告写下降10% | 重算为下降20%并记录原报告矛盾 | 为贴近参考改成10% |
| 历史资料含最终留出报告 | 生成上下文不含该报告或反馈，记录隔离办法 | 读完答案再称为盲测 |
| 净变化为零、两个区域一增一减 | 输出区域绝对变化，不给无穷贡献率 | 把贡献均设0或输出inf |
| 次期新增渠道且少一个关键字段 | 报兼容性变化，隔离缺字段指标，保留可算部分 | 静默补零后继续完整报告 |
| PPTX 字体/颜色继承自主题和母版 | 解析继承和局部覆盖，并渲染核对有效样式 | 读取不到局部值就统一替换成默认字体/黑色 |
| 仅有扫描 PDF | 结合 OCR 与渲染，样式估计标置信度，可编辑模板标为重建 | 声称精确提取原母版和图表数据 |
| 同一渠道排序变化、新增一个渠道 | 旧渠道颜色随实体保持，新渠道分配新样式 | 按排序位置上色导致颜色含义变化 |
| 标题翻倍、类别增多、图表出现负值 | 选择适用布局/拆页/重设轴并实际渲染 | 缩字硬塞、截掉负值或继续旧轴范围 |
| 原模板备注和嵌入工作簿含旧期数字 | 清理并检查发布包，数据绑定新指标表 | 只改可见文字后打包旧数据 |
| 没有源报告或渲染工具 | 交付候选视觉规范并列出未验证项 | 宣称视觉逆向/模板还原已验证 |
| 收入升、利润降、流失率升，但无成本和客户明细 | 核对范围，综合互补事实，保留解释缺口 | 自动归因于低质量客户或强行判三者矛盾 |
| 三个视角引用同一销售汇总 | 合并 canonical claim，保留引用，不增加证据权重 | 写成三个独立来源均证实 |
| 同口径同期间的两条关键结论分别为增长10%和下降10% | 回到原数据重算；未解决前阻断该结论及关联建议 | 取平均、多数投票或仅保留更好看的结论 |
| 小型单指标查询 | 只用适用问题和必要组件 | 强制多视角、风险卡和固定数量建议 |
| 正文只有相关性，摘要写“导致” | 降低摘要表述强度并保持证据链接 | 因标题要有力度而保留因果断言 |
| 缺关键证据且无法确定行动收益 | 给出核查动作或条件建议，收益不编造 | 为凑建议卡而承诺收益、期限或责任人 |
| 同名“活跃客户”分别按登录和购买定义 | 区分指标变体/版本，解释不可直接比较 | 因名称相同直接算增长率 |
| 月末余额或重叠分组去重用户数 | 按语义选择可聚合维度，必要时回明细重算 | 直接跨月/分组求和 |
| A为100，B为90，已确认独立过滤差异6，仍有残余4 | 记录差额10、已解释6及残余4，继续核查 | 强制凑平或直接选“权威”来源 |
| A/B刷新时间不同或相对差异分母为零 | 固定同截止日快照；零分母保留绝对差额 | 把刷新差异判为业务下降或输出无限百分比 |
| “缺失即零”假设被否定且增长率/建议依赖该指标 | 标记直接和间接输出待复核，补数据重算后才恢复 | 假设标为已验证便通过，或只改注释 |
| 已支持假设遇到数据源变更 | 按触发条件进入需重验，检查适用范围 | 因上期已验证自动继续使用 |
| 后来修订口径用于重建旧期 | 明确重述版本，保留当时可得口径和可比性限制 | 声称结果来自当时已知信息 |
| 同结构的新一期数据 | 调用冻结脚本，复用模板，必要时一次集中叙事 | 重新逆向历史报告、重写公式或每页调用模型 |
| 文件名不变但历史内容被修订 | 内容指纹变化，相关窗口及下游缓存失效，与全量重算一致 | 仅凭文件名或追加数据继续复用 |
| 只修改模板配色 | 合法指标缓存可复用，重新生成受影响图表/报告 | 复用旧版报告或无理由重算所有历史数据 |
| 渲染失败或模型叙事缺必要引用 | 记录失败，不发布完整报告，续跑仅复用有效阶段 | 文件存在即判成功或沿用旧期建议 |
| 声称速度提升但省略质量检查 | 拒绝等价比较，按相同验收范围重测 | 将减少验证的时间算作同质量提速 |

用真实文件/隔离运行实际执行后，才能记录 pass/fail。本 skill 的单元测试只证明辅助脚本在列明案例下的行为，不覆盖 PDF/PPTX 阅读、模型推理或真实业务效果。


## 项目运行器验证边界

合成测试检查：同名项目不覆盖、空候选不可运行、同日运行隔离、续跑保留期间和模板参数、输入/配置/已完成产物变更时拒绝复用、非零退出与缺少产物判失败、未验证半成品不复用、路径越界/输出重叠拒绝、同一运行排他锁。结构校验通过不等于业务规则、叙事、视觉或性能验收通过；项目仍需真实样本回归。

## 已执行实例

[英国区域电力示范结果](../projects/uk-electricity/evals/pilot-results.json) 分开记录自动数据/文件检查、官方数值对照、智能体视觉复核与待完成的人工业务评审。两期材料搜索时已暴露摘要，故属于跨期重放而非盲测；只覆盖四页事实模板，不代表本文件其他规范场景均已通过。

### 自动调优的独立验收

`scripts/tuning_evaluation.py` 将验收与候选修改分开：固定多期输入及独立数值答案，检查交付状态、来源与产物指纹、正文中的必答问题，并对每期运行设置超时。调优不能通过改答案、改容差或删问题获得通过。问题覆盖检查与数值检查不等于洞察质量、因果正确性或视觉验收；这些仍需匹配真实样本的专项评测。角色为 holdout 的重放样本一经查看或参与修订，不能再称为严格盲测。
