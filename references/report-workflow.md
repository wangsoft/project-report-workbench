# 报告逆向与周期生成

## PDF/PPTX 的阅读

先记录页/幻灯片数量与结构。PDF 文本层缺失时 OCR；抽取文字并保留页码，同时渲染包含图表、脚注、复杂表格的页面核对。PPTX 检查正文、形状表格、图表数据、嵌入工作簿和讲稿备注；不能仅用文本框判断全页内容。

可使用宿主可用的 PDF/演示文稿工具；无专用 skill 时用本地 PDF 渲染/OCR 或 OOXML 解析工具，记录缺失能力和未覆盖内容。不能假装看过未渲染的视觉信息。图上读数属于近似证据，不能替代原始数据精算。

提取报告各部分回答的问题、使用的指标、比较方式、细分维度、判断依据与建议。区分必须延续的企业定义和可改善的个人表达习惯。图表中的可疑数字回到数据核算，并记录参考报告矛盾。

同步按 [视觉逆向规程](visual-reverse-engineering.md) 提取配色角色、字体层级、页面网格、图表样式与可复用布局。内容证据账本与视觉证据分开，使用相同来源页 ID 关联；不把原报告的外观优点与分析正确性混为一项得分。

## 覆盖范围门槛

以参考报告为目标时，先逐页建立章节、图表、附录与关键解释的覆盖清单，记录源数据、实现方式、输出页与未解决项。不能自行以摘要版替代完整目标。计算可重建、外部证据支持、素材引用和未实现分别标记；主题覆盖、数值一致和分析质量分别验收。参考报告与数据冲突时保留两者，不能为提高匹配率调整正确计算。

## 新一期生成顺序

以下是已构建项目 的运行流程，默认由既有脚本执行稳定阶段；遵循 [执行与性能规程](execution-performance.md)。仅初次构建或实质口径/结构变化时重新生成代码，普通新一期不重新读取参考报告学习。

1. 检查文件、指标版本、可聚合维度与时间窗口；检测字段缺失、类型变化、分类新增及修订，并检查相关假设的重验触发条件。
2. 运行校验与确定性计算，生成指标表和异常清单；来源数字不一致时按 [契约](contracts.md) 定位首个分歧并核对差异桥接。关键错误、关键假设失效或未解释差异阻断受影响结论，其他部分继续。
3. 脚本执行已定义分析规则并形成精简证据包；需要综合判断时才交给模型，依 [多视角分析与叙事](analysis-synthesis.md) 检查互补问题，先总量再必要下钻，标明未回答问题及证据缺口。已知常规事实使用条件模板，避免逐页调用模型。
4. 写结论账本，核对重复发现、范围差异和实质冲突后按主题综合。新增洞察必须同样可追溯，不能因为原报告没提到就免检；保留竞争解释，不以多数意见代替核查。
5. 选择适用叙事组件和页面类型，以“结论—证据—风险/限制—行动”组织内容，由脚本绑定已验证指标与结论 ID、应用视觉规范并制图导出。长标题、多类别、负值和长表触发既定容量/布局适配，超出已验证能力时再介入处理，不沿用旧期数据或失效坐标范围。
6. 重算关键数字、检查合计和图文一致性，确认输出不依赖失效或待重验的关键假设；执行视觉规程的结构与逐页渲染检查，记录设计继承、适配和修正。按用户格式交付报告及简洁限制说明。

正文优先呈现会影响决策的变化及其证据；方法细节、完整数据质量记录放附录/运行目录。缺证据时明确“需核查”，给出获取证据的下一步，不写成已知原因。

报告形态遵从用户指定；未指定时先用可审核的文本分析稿确定结论，再选择适合读者的格式。不要为了模仿原报告而复制已失效章节，也不要把每种方法都塞入正文。
