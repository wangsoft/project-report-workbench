# 输入、规则与证据契约

使用 JSON/YAML 或等价结构即可；以下字段是语义要求，不要求引入数据库或框架。

## 输入清单与数据契约

每个 period 记录：期间起止、截止日、时区/财务日历、是否完整、数据及报告路径与 SHA-256、数据可用日期、业务范围、版本、训练/调参/最终留出角色。报告对应的数据可能含修订，必须核对版本。重建历史时只能用截至当时已知的数据和背景。

每张事实表记录：Sheet/范围、表头行、行粒度、主键/关联键、字段原名及规范名、类型、单位、币种、缺失定义、合法值、汇总行规则、关联基数。每个指标记录公式、过滤条件、分母、权重、比较基期、舍入精度、核对容差与口径版本。容差由单位和用途决定，不机械使用统一 `1e-6`。

## 指标语义与版本

在已有数据契约内维护指标定义，不另建重复口径库。每个指标使用稳定 `metric_id` 与明确版本，至少回答：

- **业务含义与用途**：普通语言定义、服务的决策、来源或定义责任方（未知则标未知）、目标/好坏方向及其依据。没有依据不补行业阈值。
- **计算与依赖**：公式、分子/分母、依赖指标及版本、基础/比率/累计/派生类型，输入到结果的路径。
- **范围与时间**：主体、包含/排除对象、发生日或入账日、时区、期间完整性、有效起止日期和定义被获知的日期。
- **粒度与可聚合性**：一行代表什么、允许分析的维度、跨哪些维度可加。余额等时点指标不能直接跨时间求和，比率应重算分子分母；去重用户数不能把重叠分组相加。
- **例外与变更**：退款、取消、重复、缺失、零/负分母等处理；变更理由、替代版本和可比性策略。

同名异义的指标分配不同 ID 或明确变体；别名不能自动证明定义一致。新口径不直接套用到旧期形成增长率：选择同口径重算或分别披露不可比。历史重建保留当时已知口径；如需用后来修订的数据重述历史，标记为重述，不冒充历史时点可得结果。

## 指标差异核对

当来源、报告或重算结果不一致时，在现有冲突记录中增加 `reconciliation` 信息，不新建另一套事实账本：

1. **固定快照**：记录 A/B 来源哈希、数据刷新/截止时间、指标版本、期间、粒度、计算路径和原始结果。来源被称为权威不代表免于核验。
2. **量化差异**：保留有符号差额 `A-B`、绝对差额和明确分母的相对差异。分母为零时不输出无穷比例，使用绝对值或双方约定尺度；容差来自单位/舍入/业务要求，不能套用通用行业百分比。
3. **逐层定位**：对齐时间/时区、范围/过滤、去重、关联基数、空值处理、聚合及舍入。对每一步记录行数、关键合计和不匹配键，找到第一个分歧点；明细抽样帮助解释，但差异金额需全量核对。
4. **差异桥接**：用互斥且不重复计数的差异项解释总差额，记录残余。若调整顺序会改变贡献分配，写明顺序；无法可靠拆分时保留未解释残余，不强制凑平。
5. **处理与复核**：区分计算缺陷、口径差异、刷新延迟、舍入及未知。修正本次计算、隔离受影响结论或依据已知正式定义选择来源；不得自行修改上游系统。记录重算证据、残余及受影响报告。

处理状态用 `open`、`resolved`、`accepted_difference`；低于容差也记录差异来源，不能掩盖已知系统性错误。定义冲突无权裁决时保持 open，仅阻断依赖它的结论。桥接记录包含 `source_a/source_b`、`gap`、`tolerance_basis`、`first_divergence`、`adjustments`、`residual`、`resolution_evidence` 和关联 `claim_ids`。

## 假设生命周期与失效传播

每个实质假设赋予 `assumption_id`，记录内容、类型（数据/业务/统计/技术）、提出依据、适用范围、依赖指标/规则/结论 ID、错误后果、验证方法、证据、最近检查日期与重验触发条件。若使用高/中/低置信描述，附理由，不转成虚构概率或自动风险分。

状态明确区分 `unverified`、`supported`、`refuted`、`needs_recheck`、`superseded`；“已经检查过”不等于支持。记录每次状态变化及证据，保留旧版本。影响关键结论但证据不足的假设，应补证据、做敏感性分析或隔离相应结论，不仅在低置信时才检查。

每期先检查数据源、字段含义、缺失模式、业务规则、时间窗口或方法前提是否变化。触发变化时把相关 supported 假设转为 needs_recheck；不能跨期沿用而不检查适用范围。

假设被否定或需要重验时，沿依赖关系查找直接与间接受影响的指标、派生指标、claim、建议、图表和报告页，将其标为待复核/待重算，避免继续作为确定结论使用。依赖信息缺失时不能假称影响已完整追踪：保守核查相关分析链并报告覆盖缺口。重算后用新证据更新状态，不能仅修改假设标签就解除阻塞。

例如“空销售额表示零销售”被同步故障反驳：隔离相关行，重新评估总额、增长与区域贡献，检查受影响历史报告。保存原报告与修订说明；只在已有授权范围内重生成本地版本，不自动覆盖已发布报告或发送更正消息。

## 结论账本

一条结论示例（数字为合成示例）：

```json
{
  "claim_id": "C-001",
  "period": "2026-02",
  "kind": "computed_fact",
  "text": "销售额较上期下降20%",
  "metric_id": "net_sales",
  "value": "-0.20",
  "unit": "ratio",
  "evidence": [
    {"artifact": "metrics.json", "key": "net_sales.current", "value": "80"},
    {"artifact": "metrics.json", "key": "net_sales.previous", "value": "100"}
  ],
  "calculation": "(80-100)/100",
  "lineage": {
    "input_manifest": "input-manifest.json",
    "source_locator": "Sales!A2:F51",
    "filters": "period=2026-02; exclude subtotal",
    "transform_version": "v1"
  },
  "reference_location": "human.pdf#page=3",
  "status": "recomputed",
  "limitations": []
}
```

`kind` 区分 computed_fact、external_fact、hypothesis、recommendation。解释和建议可以没有数值，但需关联事实 claim_id，并列出假设、所缺证据及适用条件。`status` 区分已重算、来源核实、待验证、矛盾；格式合法不是事实正确。训练账本的 `reference_location` 不传给生成过程。

涉及指标的结论记录 `metric_version`；所有结论按需记录 `assumption_ids`、上游 `depends_on_claim_ids`。假设失效后的 `review_status` 使用 `current/needs_review/invalidated`，与数值是否曾重算的 `status` 分开；曾经重算正确并不保证当前前提仍成立。依赖关系不得自循环，缺失引用应显式报错或标为影响覆盖缺口。

## 多视角发现与冲突记录

需要跨问题综合时，在原账本增加以下字段，不再维护第二套数值：

- `question_ids`、`lens`、`theme`：回答哪些问题、使用什么视角、归属什么业务主题。
- `importance_reason`：决策影响、范围及紧迫性的依据；不能编造打分。
- `supports`、`counterevidence`：支持和反证的 claim ID；无反证记录不等于已证明没有反证。
- `alternative_explanations`、`evidence_gaps`：尚可成立的解释、区分它们所缺的资料。
- `canonical_claim_id`：同一事实去重后的 ID；重复视角引用不算独立证据。
- `chart_recommendation`：图形要回答的问题、指标 ID、比较范围；图形本身不增加证据强度。

另记录必要的冲突：`conflict_id`、`claim_ids`、类型（范围差异/算术矛盾/竞争解释）、核查动作、结果、未解决部分、受影响结论/行动及状态。纯互补现象不强制创建冲突。执行规则见 [多视角分析与叙事](analysis-synthesis.md)。

## 规则卡与发布清单

规则卡至少有：ID、类型（企业口径/方法/呈现）、触发条件、动作、例外、来源、支持期和反例、状态、测试 ID。运行时规则不含历史参考报告原文或留出期结论；完整训练证据留在开发记录里。

发布清单记录：本 skill 运行工具版本、项目配置/脚本/模板版本及内容哈希、规则 ID、数据契约版本、依赖、评测设置、生成输入隔离办法、样本划分、已执行结果、未验证范围。`candidate` 表示可试用；`validated_for_scope` 仅表示在列明的业务/口径/时间范围内有证据，不代表任何新数据都适用。
