# 脚本优先的周期报告流水线

首次构建负责理解业务并生成可执行能力；后续运行优先复用已验证的代码与模板。本 skill 按项目配置构建并调度流水线，处理需要判断的例外。不要每期重新逆向报告、选择基础方法或重写稳定计算。

## 两种模式

**构建/升级**：使用训练材料确认契约、规则与视觉规范，生成脚本和模板，验证计算与留出效果，测量速度并冻结版本。口径/结构/模板或任务范围的实质变化触发升级；无真实数据时只能交付候选规程，不能假称可运行流水线已生成。

**周期运行**：读取已发布版本与本期输入，检查兼容性和假设，执行计算、证据生成、必要叙事、制图导出与验收。新增类别若契约已有处理规则可直接运行；关键字段含义变化则隔离受影响部分并回到升级流程，不让模型临时“猜着修”。

## 责任分配

| 环节 | 默认执行方式 | 模型介入条件 |
|---|---|---|
| 读取、字段映射、清洗、粒度与关联检查 | 已验证脚本＋版本化配置 | 新结构/未知业务语义 |
| 指标、比较、贡献分解、对账 | 确定性脚本，输出数值、单位、口径版本与来源 | 选择新方法、裁决尚未明确的口径 |
| 已定义异常规则与常规发现 | 脚本检测并生成候选事实、证据 ID | 判断异常的重要性、竞争解释和外部背景 |
| 数字与固定描述 | 带条件和缺失分支的模板 | 跨主题综合、限制解释、行动建议 |
| 图表、模板填充、页序、导出 | 已验证生成脚本 | 新页面类型、超出既定布局容量 |
| 核对与验收 | 自动检查＋既定视觉验收 | 语义判断与实际页面观察 |

简单例行报表可不调用模型生成叙事；综合分析报告通常把精简证据包交给模型一次集中撰写，再校验回填。次数是优化方向而非硬性上限；新证据、冲突或修订需要时增加调用并记录原因。多视角是问题清单，不等于每个视角各调用一次模型。

## 生成脚本的最小接口

按业务复杂度组织代码，小任务可使用一个脚本的多个阶段，不强制微服务、工作流框架或大量文件。使用本 skill 的统一入口 `scripts/project_manager.py` 调度项目阶段（见 [项目配置](project-workflow.md)）；业务脚本按配置提供参数，其 `--help`、输入清单、输出目录、阶段/续跑选项与退出行为必须真实可用。

推荐阶段边界：

```text
输入与兼容性检查 → 规范化与计算 → 证据包
                                  ↓
                       模板叙事 / 模型综合
                                  ↓
                      图表与报告导出 → 验收
```

计算结果用 JSON/表格供后续阶段读取，至少包含指标与结论 ID、精确值、单位、来源、质量状态和适用版本。模型输入保留关键反证、数据缺口和未解决冲突；不能只截取 Top-N 正面发现。摘要外的数据通过稳定定位按需下钻，不默认把整份 Excel 或历史报告塞进上下文。

模型输出以带 claim ID 的结构化叙事返回，数值尽量通过引用交给脚本格式化。验证引用存在、适用状态和必要字段后再填模板；解释强度仍需语义检查，JSON 合法不能代替质量验收。

模型调用可由宿主智能体完成：脚本先生成证据包，智能体写入叙事文件，再由入口恢复后续阶段；无需为项目 另接 API 或保存密钥。若选择直接 API 调用，遵守用户已有环境、授权与费用约束。

阶段产生明确成功/失败状态、输入指纹、代码/配置版本和输出清单；非零退出不能被视为完成，失败后不复用半成品。输出写临时文件，检查后再原子发布到本次运行目录；不覆盖已发布旧报告。规范指标与依赖 ID 是单一事实来源，禁止在脚本、文本和图表里各维护一套公式。

## 缓存与增量

遵守 [数据处理规程](data-processing.md) 的缓存规则，进一步按阶段限定依赖：

- 规范化缓存：来源内容、Sheet/范围、schema、映射、清洗代码与契约版本。
- 指标缓存：规范数据分区、历史窗口、公式/过滤、维表版本、假设状态与有效配置。
- 叙事缓存（若启用）：完整证据包、任务、规则、模型/提示词设置及背景截止日。只缓存已验收叙事；日期、指标或假设变化后不得继续复用旧结论。
- 图表/报告缓存：指标/叙事、模板、视觉规范、字体、生成代码、目标格式与相关渲染环境。

不按文件名、路径或修改时间单独判断内容未变。验证缓存清单和产物完整性；同一文件改内容、历史回补、退款/删除、晚到数据都需失效。滚动窗口、累计值和 cohort 可能连带影响多个期间，按真实依赖重算；依赖范围无法确定时全量重算相关阶段，不以“增量”名义直接追加造成重复。

仅模板变化可复用合法的指标缓存；仅本期数据变化不必重新逆向设计；上游变更沿依赖传播到下游。并发写入使用运行隔离或锁，未实现时顺序执行。缓存不替代当前质量门槛，过期假设和失败校验不能因缓存命中被绕过。

## 速度与成本验收

首次构建与周期运行分别计时，不把构建成本混成每期成本，也不把热缓存速度宣称为首次速度。固定代表性数据规模、历史窗口、页数、输出格式、机器、依赖及模型设置，记录：

- 端到端耗时，及读取/校验、计算、模型、制图导出、验收各阶段耗时。
- 缓存状态与命中范围、处理行数/文件大小、输出页数、失败和重试。
- 模型调用次数、输入/输出 token、费用与其来源；拿不到的数据记 null/未知，不能用命令次数冒充模型调用次数。
- 峰值内存及测量工具/范围；仅测主进程时不得称全流水线峰值。

本 skill 的 `scripts/benchmark_command.py` 可测任意已存在命令的端到端墙钟耗时、失败和重复运行统计；它不会清缓存、测 token 或采集内存，也不会生成业务报告。每次命令必须写独立运行目录或具备幂等性。冷启动、热缓存、历史修订测试应分别准备环境，不能仅换标签充当不同场景。

先做一次冷缓存、一次热缓存和一次历史修订的正确性对照；需要比较时再在相同设置下重复计时，报告样本量、中位数和范围，不用极小样本推算可靠 P95。核对关键指标、证据状态与无缓存全量重算相同，不能以二进制报告哈希不同判数值错误。

用户有时延/成本要求时记录目标及测量口径；没有则先报告实测基线和最大瓶颈，再确定优化，不编造“几秒生成”。优先消除重复 Excel 解析、模型重复读数据/逐页生成和不必要重渲染。优化后需保持同样质量门槛；不能减少事实校验、删除反证或省略既定视觉验收来制造提速。

模型不可用时，只在契约允许的模板事实稿模式下交付，明确缺少综合判断；不把旧建议混入新报告，也不声称与完整分析等价。未拿到业务样本时，交付性能测量入口和待验收项，不报告业务速度提升。

## 已执行的示范测量

英国区域电力项目使用 --cache-dir 启用标准化、计算和渲染缓存；check/verify 每次执行。协议见 [项目生命周期](project-lifecycle.md)。同一运行续跑仍使用整体指纹，跨运行复用采用声明依赖的阶段键。

workspace/uk-electricity-benchmark-02/benchmark.json 保存三次冷缓存、三次热缓存、三次无缓存及样式修改、历史修订对照。中位数分别为 0.698、0.297、0.687 秒；热缓存相对无缓存约 2.31 倍。证据与 PDF 字节相等，修订场景与完整重算一致。模型调用为零，token 与峰值内存未测量；不含初始建设、视觉复核及人工业务评审。不能外推至大型数据或模型叙事报告。

0.3.0 十五页版本的最新基准在 workspace/uk-electricity-benchmark-04/benchmark.json：冷缓存 1.189 秒、热缓存 0.468 秒、无缓存 1.164 秒（各三次中位数），约 2.48 倍。外部文献、背景清单和地图已预先准备，检索与人工整理不在该速度内；原四页数据不得用于代表新版速度。

经验学习分为构建期与生产期：构建期由宿主比较历史材料、检索规则、归因和修改候选；生产期运行已经验证的脚本与模板。脚本输出可记录应用的经验 ID 与内容哈希（零售案例为 experience-applied.json）。不要把构建期的模型工作计为零，也不要用小规模合成数据的运行时间代表完整 PDF/PPTX 的生成速度。规则池的标题路由最多返回八项，显式打开正文，避免把整个经验库每期装入模型上下文。
